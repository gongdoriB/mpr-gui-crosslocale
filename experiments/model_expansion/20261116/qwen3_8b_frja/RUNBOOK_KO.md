## 배치 크기 (사용자가 정해야 함)

예전 Qwen3-VL-8B 실행은 REL이 **배치 4**(`--strict-batch-size`, 실행 계약 `batch_size: 4`, 예측 18,432건 모두 `batch_size` 4), 실험 A가 배치 3(한 쌍 = O, T, R 한 배치), 6x6이 배치 4였다. 작업 지시서는 REL이 배치 1이었다고 적었으나 실행 계약과 `run_full.sh`(`--batch-size $BATCH --strict-batch-size`, 선택값 4)는 4를 가리킨다. 배치 1 점검(2026-11-14, 같은 4090급 서버, 28문항 O/R 672행)에서 배치 4와 답이 같은 비율은 0.9866(663/672)이었다.

| 선택 | 환경변수 | 결과 |
|---|---|---|
| REL 배치 1 (현재 기본값) | `REL_BATCH=1` | 예전 4개 언어 REL(배치 4)과 계산 조건이 다르다. 중앙값 0.700초/회 -> 약 5.1시간. 같은 쌍이 한 배치에 묶이지 않아 패딩 영향이 없다. |
| REL 배치 4 | `REL_BATCH=4` | 예전 REL과 같은 조건. 중앙값 0.587초/회 -> 약 4.2시간. `--strict-batch-size`가 자동으로 붙는다(메모리 부족 시 쪼개지 않고 멈춤). |
| 실험 A 배치 3 (기본값) | `EXPA_BATCH=3` | 예전 실험 A와 같음. 중앙값 0.613초/회 -> 약 1.6시간. |
| 실험 A 배치 1 | `EXPA_BATCH=1` | 약 1.8시간(0.700초/회 가정). O/T/R이 서로 다른 배치. |

일관성 점검의 배치는 `CC_BATCH`(기본값 = `REL_BATCH`)로 따로 정할 수 있다. 예전 점검 기준(배치 4)과 같은 조건으로 보려면 `CC_BATCH=4`. 같은 결과 폴더에 다른 배치 크기로 다시 돌리면 실행기가 실험 지문 불일치로 거부한다.

## 일관성 점검

- 대상: 예전 REL 전체 실행(2026-11-07, 4090, 배치 4)의 정식 추론 18,432건 중 600건. 조건 x 질문 언어 x 화면 언어 칸 52개(O는 16개 언어쌍 모두, R/C/F는 서로 다른 언어 12쌍; 같은 언어쌍에서는 네 조건의 프롬프트가 같아 O 하나만 정식 추론이다)에서 칸당 11개 + 나머지 28개를 시드 20261116으로 뽑았다. "4조건 x 16언어쌍 모두"는 이 이유로 불가능하다.
- 실행: 바뀌지 않은 6개 언어 REL 실행기로, 본 실행과 같은 코드 경로. 결과는 본 결과와 다른 폴더.
- 출력: `consistency_agreement.json`에 생성 라벨 일치율(전체, 조건별, 언어쌍별, 조건 x 언어쌍별), 정답 여부 일치, 정확도(예전/지금), 정답 확률 차이, 예전·지금 환경 정보. 합격 기준은 두지 않았다. 예전 배치 4 대 배치 1 점검이 0.9866이었으므로 1~2% 차이는 배치와 커널만으로 생길 수 있다. 0.90 아래면 데이터·이미지·환경 차이를 먼저 의심한다(해석, 기준은 임의).

## 미검증 (2026-11-16 추가, Fable 검토 반영)

- 서버 저장소의 추론 코드 12개 해시: 설정 단계가 검사하고, 다르면 모델을 받기 전에 멈춘다.
- 새 서버(vast4090c)에서의 실제 속도와 fr/ja 입력에서의 VRAM.
- 허깅페이스에서 fr/ja 이미지 받기: 가짜 응답으로만 시험했다. 이번에는 이미지 묶음을 올린다.
- 모델 파일 바이트 수: 16.5~18.5GB 범위로만 검사한다.
- 일관성 점검(600회, 배치 4)은 예전 배치 구성을 재현하지 않는다. 그래서 일치율은 이미지·프롬프트가 크게 어긋난 경우(0.90 미만)를 잡는 거친 점검일 뿐이다. "서버 동등성 확인"이라고 쓰지 않는다. 큐가 끝난 뒤, 인스턴스를 지우기 전에 예전 배치를 통째로 다시 돌리는 점검을 따로 한다. 모델 캐시는 남아 있다.
- 실험 A의 T_retry 실행 안의 O/R은 본 실행의 O/R과 배치 동반 행이 달라 소수 행에서 답이 다를 수 있다. 민감도 분석은 같은 실행 안의 O/R과 비교한다.
